# ZAMELANO

Двуязычная статическая концепция онлайн-бутика женского белья. Русский и английский, адаптивная главная со слайдером, каталог, карточки, поиск, фильтры, избранное, корзина, журнал, FAQ и подготовка заявки в Telegram.

В хедере используется фирменный логотип без розового фона. Ключ из логотипа заменяет отдельные декоративные стрелки в кнопках, включая «Подробнее». Прозрачные PNG-маски окрашиваются золотым градиентом в CSS; промпты — в `BRAND_ASSET_PROMPTS.txt`.

Текстовый слайдер на главном экране содержит три слайда. Он переключается кнопками, точками, клавишами ←/→ и Home/End, а также горизонтальным свайпом. Автоматического перелистывания нет. Неактивные слайды скрыты от вспомогательных технологий; настройка уменьшения движения отключает анимацию. Тексты всех трёх слайдов переведены на русский и английский в `site/app.js`.

**Демонстрация:** https://kibosh13.github.io/zamelano/

## Структура

- `site/` — редактируемые HTML/CSS/JS, JSON-каталог и необходимые изображения. Эти файлы написаны вручную; это исходники, а не результат локальной сборки.
- `scripts/check_project.py` — проверка состава Git, известных форматов секретов и ссылок на ресурсы.
- `scripts/prepare_site.py` — подготовка демо или будущей боевой версии с разными правилами индексации.
- `.github/workflows/deploy-demo.yml` — проверка, обновление ветки `gh-pages` и публикация GitHub Pages при изменениях `main`.
- `IMAGE_PROMPTS.txt` — промпты иллюстраций, созданных ImageGen.

Исходники находятся в `main`; статическая демонстрация — в `gh-pages`. В Git не входят `.env*`, зависимости, базы, логи, кэши, локальные сборки, архивы и служебная конфигурация Sites. Чувствительные реквизиты и точный адрес из карточки ИП исключены из публичного проекта.

## Запуск и изменение

```sh
python3 -m http.server 8080 --directory site
```

Откройте http://localhost:8080/. Для чтения `catalog.json` нужен HTTP-сервер. Устанавливать зависимости не требуется.

Оформление: `site/styles.css`. Тексты и переводы: `site/app.js`. Каталог: `site/catalog.json`. `price` — число в рублях или `null`; `stock` — количество или `null`, `0` означает отсутствие товара. `sizes` и `colors` содержат варианты производителя. Изображения находятся в `site/assets/`.

Обычное обновление:

```sh
git add site README.md scripts .github .gitignore
python3 scripts/check_project.py
node --check site/app.js
git commit -m "Update ZAMELANO catalogue"
git push origin main
```

GitHub Actions обновляет только изменившиеся файлы в `gh-pages`. Изображения не генерируются заново и не перекодируются, архивы в репозиторий не добавляются. Публикация Pages использует артефакт Actions, а не архив в Git.

## Индексация

Демонстрация всегда получает `noindex, nofollow, noarchive` для `robots`, `googlebot` и `yandex`. Индексация блокируется метатегами HTML. Crawlers могут прочитать эти теги; `robots.txt` не мешает чтению. На GitHub Pages файл robots.txt внутри `/zamelano/` не заменяет robots.txt в корне домена.

Для будущего боевого сайта предусмотрен отдельный режим:

```sh
python3 scripts/prepare_site.py --target production --base-url https://YOUR-PRODUCTION-DOMAIN/ --output build/production
```

Он создаёт `index, follow`, корректные canonical/OG image, разрешающий robots.txt и sitemap.xml. Окончательный домен обязателен. Эта команда только готовит файлы: боевой сайт не развёрнут и его текущие настройки не изменяются. После запуска проверьте robots.txt в корне боевого домена и удалите ограничения индексации у хостинга.

## Ограничения демонстрации

- Реальные модели, фото, размеры, цены и остатки отсутствуют в брифе: три карточки отмечены как концепции, неизвестное — `[заполнить]` / `[fill in]`.
- Картой и СБП платить нельзя; эквайринг, касса и чеки не подключены.
- Нет серверной базы заказов, кабинета, CRM, CMS и админки. Данные корзины, избранного и языка хранятся в браузере.
- Формы готовят текст. Посетитель сам открывает Telegram и отправляет сообщение. Автоматических уведомлений через бота нет.
- Расчёт курьерской доставки, трекинг, сертификаты, промокоды и бонусы не реализованы; их условия не заданы.
- Юридические документы и полные публичные реквизиты необходимо согласовать и заполнить.

GitHub Pages подходит для этой витрины. Полноценная торговля потребует серверного магазина/CMS, реального каталога, оплаты, кассы и утверждённых документов.
