# ZAMELANO

Двуязычный сайт онлайн-бутика с собственной PHP-админкой на боевом хостинге и отдельной статической демонстрацией на GitHub Pages. Русский и английский, адаптивная главная со слайдером, каталог, карточки, поиск, фильтры, избранное, корзина, журнал, FAQ и подготовка заявки в Telegram.

В хедере используется фирменный логотип без розового фона. Полный ключ из логотипа, включая длинную ножку и нижнюю полку буквы L, заменяет стрелки во всех кнопках и ссылках, в слайдере, карточках, корзине, формах и выпадающих списках. Знак выделяется в CSS из той же прозрачной маски полного логотипа без изменения пропорций и окрашивается золотым градиентом. Происхождение графики и параметры выделения — в `BRAND_ASSET_PROMPTS.txt`.

Текстовый слайдер на главном экране содержит три слайда. Он переключается кнопками, точками, клавишами ←/→ и Home/End, а также горизонтальным свайпом. Автоматического перелистывания нет. Неактивные слайды скрыты от вспомогательных технологий; настройка уменьшения движения отключает анимацию. Тексты всех трёх слайдов переведены на русский и английский в `site/site-content.json`.

**Демонстрация:** https://kibosh13.github.io/zamelano/

## Структура

- `server/` — PHP-движок, API, закрытая админка и выдача файлов медиатеки. В сборку GitHub Pages не входит.
- `tests/cms_integration.py` — изолированные проверки настоящего PHP API, без запросов к боевому сайту.
- `site/` — редактируемые HTML/CSS/JS, JSON-каталог и необходимые изображения. Эти файлы написаны вручную; это исходники, а не результат локальной сборки.
- `scripts/check_project.py` — проверка состава Git, известных форматов секретов и ссылок на ресурсы.
- `scripts/prepare_site.py` — подготовка демо или будущей боевой версии с разными правилами индексации.
- `.github/workflows/deploy-demo.yml` — проверка, обновление ветки `gh-pages` и публикация GitHub Pages при изменениях `main`.
- `IMAGE_PROMPTS.txt` — промпты иллюстраций, созданных ImageGen.

Исходники находятся в `main`; статическая демонстрация — в `gh-pages`. В Git не входят `.env*`, зависимости, базы, логи, кэши, локальные сборки, архивы и служебная конфигурация Sites. Исходная карточка ИП и её банковские реквизиты не публикуются. Сведения об операторе из переданных для публикации юридических документов сохранены в их текстах.

## Запуск и изменение

```sh
python3 -m http.server 8080 --directory site
```

Откройте http://localhost:8080/. Для чтения `catalog.json` нужен HTTP-сервер. Устанавливать зависимости не требуется.

Оформление: `site/styles.css`. Начальные тексты, переводы и настройки: `site/site-content.json`. После установки на сервер содержимое редактируется в админке и хранится отдельно от исходников. Каталог: `site/catalog.json`. `price` — число в рублях или `null`; `stock` — количество или `null`, `0` означает отсутствие товара. `sizes` и `colors` содержат варианты производителя. Изображения находятся в `site/assets/`.

Обычное обновление:

```sh
git add site README.md scripts .github .gitignore
python3 scripts/check_project.py
node --check site/app.js
git commit -m "Update ZAMELANO catalogue"
git push origin main
```

GitHub Actions обновляет только изменившиеся файлы в `gh-pages`. Изображения не генерируются заново и не перекодируются, архивы в репозиторий не добавляются. Публикация Pages использует артефакт Actions, а не архив в Git.

## Индексация

Демонстрация всегда получает `noindex, nofollow, noarchive` для `robots`, `googlebot` и `yandex`. Индексация блокируется метатегами HTML. Crawlers могут прочитать эти теги; `robots.txt` не мешает чтению. На GitHub Pages файл robots.txt внутри `/zamelano/` не заменяет robots.txt в корне домена.

Для будущего боевого сайта предусмотрен отдельный режим:

```sh
python3 scripts/prepare_site.py --target production --base-url https://YOUR-PRODUCTION-DOMAIN/ --output build/production
```

Он создаёт `index, follow`, корректные canonical/OG image, разрешающий robots.txt и sitemap.xml. Окончательный домен обязателен. Эта команда только готовит файлы. На боевых zamelano.com и zamelano.ru используется PHP-версия. Главная и документы открыты для индексации; админка и предпросмотр закрыты. Настройку индексации главной и документов можно менять в админке.

## Ограничения демонстрации

- Реальные модели, фото, размеры, цены и остатки отсутствуют в брифе: три карточки отмечены как концепции, неизвестное — `[заполнить]` / `[fill in]`.
- Картой и СБП платить нельзя; эквайринг, касса и чеки не подключены.
- В статической демоверсии нет PHP-админки. Нет серверной базы заказов, кабинета и CRM. Данные корзины, избранного и языка хранятся в браузере.
- Формы готовят текст. Посетитель сам открывает Telegram и отправляет сообщение. Автоматических уведомлений через бота нет.
- Расчёт курьерской доставки, трекинг, сертификаты, промокоды и бонусы не реализованы; их условия не заданы.
- Полные юридические тексты опубликованы из переданного комплекта. Для будущих файлов на сервере подготовлена отдельная настройка ссылок.

GitHub Pages подходит для этой витрины. Полноценная торговля потребует реального каталога, подключения оплаты и кассы. На боевом хостинге уже есть редактор содержимого и каталога; он не является платёжным или складским сервисом.

## Документы и cookie

В `site/legal-documents.json` находятся полные тексты пяти готовых документов, переданных владельцем для публикации 24.10.2026: политика, оферта, согласия на обработку данных при заявке, на рассылку и на публикацию отзыва. Сведения об операторе из этих утверждённых документов сохранены. Исходные Word-файлы и инструкция по размещению в репозиторий не включены. Текст не переписан: оформление, списки и таблицы адаптированы для браузера. Незаполненные ссылки из Word при отображении заменяются рабочими ссылками на сайт, политику и согласие.

Постоянные адреса:

- `documents.html#privacy` — политика;
- `documents.html#offer` — оферта;
- `documents.html#order-consent` — обработка данных при заявке;
- `documents.html#newsletter-consent` — рассылка;
- `documents.html#review-consent` — публикация отзыва.

На главной те же ссылки открывают окно чтения. Заполненная форма сохраняется под ним, закрытие возвращает к форме. Корзина содержит ссылки на политику и оферту. Обмен/возврат и реквизиты ведут к соответствующим разделам оферты. В форме остаётся обязательный, заранее не отмеченный чекбокс; подготовить заявку можно после его установки. Дата, время и версия политики добавляются в текст Telegram. Сайт ничего не отправляет сам. Рассылка, сбор отзывов и подпись согласий на публикацию не подключаются.

`site/document-links.json` — **начальные настройки ссылок на файлы для статической версии**. На боевом сайте файлы выбираются через раздел «Документы» админки, URL медиатеки подставляется автоматически. Пока значения `files` равны `null`, посетитель читает HTML-версию. Заполните URL у нужного ID — появится кнопка «Открыть файл». Поддерживаются HTTPS/HTTP и относительные адреса; другие схемы отклоняются. `siteUrl` можно оставить `null`: адрес сайта подставится по текущему домену. Файловые ссылки не меняют текст HTML-версии: при обновлении документа синхронно обновляйте `legal-documents.json`, дату комплекта и версию политики.

Cookie-уведомление показывается новому посетителю один раз и скрывается кнопкой «Понятно». Выбор хранится локально под ключом `zamelano-cookie-notice`. Ссылка «О cookie» в футере открывает уведомление повторно. Необязательные счётчики, аналитика и реклама не подключены. Это уведомление не является согласием на рассылку, обработку заявки или публикацию отзыва.

Интерфейс документов и cookie переведён на RU/EN. Юридические тексты остаются в исходной русской редакции. Обе HTML-страницы демо получают `noindex`; режим production снимает ограничение с обеих. Документы описывают в том числе будущий полноценный магазин; их публикация не подключает оплату, кабинет или доставку.


## Собственная админка на хостинге

Вход: `https://zamelano.com/admin/` или `https://zamelano.ru/admin/`. Оба домена используют общее содержимое. Сессия входа отдельная на каждом домене, логин и пароль одинаковые.

Через интерфейс можно:

- добавлять, редактировать, дублировать и убирать в корзину товары; менять цены, наличие, размеры, цвета, галерею и категории;
- редактировать тексты и кнопки RU/EN, слайды, порядок и видимость разделов, статьи, FAQ и отзывы;
- загружать фотографии JPG/PNG/WebP и документы PDF/DOCX, переносить текст из Word и редактировать юридические документы по абзацам и таблицам;
- менять меню, контакты, SEO, индексацию, цвета, шрифты, скругления, логотипы и фотографии;
- сохранять черновик, открывать закрытый предпросмотр, публиковать общую версию на оба домена, восстанавливать предыдущие версии.

Рабочий порядок: «Сохранить черновик», «Предпросмотр», затем «Опубликовать». До публикации посетители видят предыдущую версию. У товара со статусом «Черновик» нет публичной карточки. Корзина товаров обратима; окончательного удаления через интерфейс нет. Конфликт параллельных сохранений блокируется, чтобы один редактор не перезаписал другого.

Первый доступ создаёт владелец по одноразовой ссылке. На сервер заранее загружается только SHA-256 отпечаток одноразового кода с ограниченным сроком действия в `owner-setup.json` вне web-каталога. Пароля по умолчанию нет. После создания владельца повторная настройка запрещена. Пароль хранится только в виде хеша; менять его можно в разделе «Доступ владельца». Письма сброса пароля не подключены: для восстановления нужен доступ владельца к панели хостинга и резервной копии закрытого хранилища.

### Данные и резервные копии

Требования: PHP 8.3+, расширения GD, fileinfo, mbstring, ZipArchive, DOM, HTTPS. На ROKMERE нет PDO SQLite, поэтому движок использует файловое JSON-хранилище с блокировкой и атомарной заменой. Веб-корни: `/home/u10040/www/zamelano.com` и `/home/u10040/www/zamelano.ru`. Общее закрытое хранилище: `/home/u10040/data/zamelano-cms` (права каталогов 0700, файлов 0600). В другом окружении путь задаётся серверной переменной `ZAMELANO_STORAGE`, обязательно вне каталога сайта.

В хранилище находятся состояние, хеш пароля, приватные сессии, медиафайлы, последние 50 версий и журнал действий. Оно не отправляется в GitHub и не заменяется при обновлении кода сайта. Перед обновлением сохраняйте резервную копию этого каталога через панель хостинга. Удаление хранилища сбросит содержимое и доступ — не используйте его для обычного обновления.

Кнопка «Скачать копию содержимого» выгружает только тексты, настройки, каталог и ссылки. Пароли и сессии не выгружаются. Бинарные медиафайлы в эту JSON-копию не входят: для переноса фотографий и документов нужна отдельная копия закрытого каталога `media`. Импорт копии восстанавливает черновик; публикация выполняется отдельно.

### Подготовка и проверка

```sh
python3 scripts/prepare_site.py --target production --base-url https://zamelano.com/ --output build/cms-local
python3 tests/cms_integration.py
find server -name '*.php' -exec php -l {} \;
node --check site/cms-client.js
node --check server/admin/admin.js
```

Тесты запускают два локальных PHP-сервера с общим временным хранилищем: проверяют авторизацию, CSRF, ограничение попыток входа, черновик и публикацию, работу двух доменов, конфликты, загрузки, копии и смену пароля. Все тестовые данные удаляются после проверки.

Для внешнего хостинга подготовьте отдельную production-сборку с соответствующим `--base-url` для каждого домена. Загружайте её через файловый менеджер браузера, сохраняя существующий `assets/` и закрытое хранилище. Главная использует `index.php`; исходный статический `index.html` нужно перенести в локальную резервную копию или закрытый архив. PHP-шаблоны защищены от прямого открытия. В GitHub Pages отправляется только сборка `--target demo`: там нет серверной части, пользовательских загрузок и доступа владельца.
